# Results claim audit

Audit of numeric and trend claims in `paper/sections/results.tex` and the
quantitative claims retained in `paper/sections/conclusion.tex`. "Matches"
means the statement/table agrees with the named generated CSV or summary,
re-derived from the CSV (not copied). Every source path below exists in the
repository, and every folder's settings are recorded in
`agv_code/agv_code/results_manifest.json` (command, git commit, seeds, jobs,
AGVs, track rule, date, Python/package versions, CPU model).

Since the macro pipeline, every result numeral in the paper comes from
`agv_code/agv_code/make_paper_numbers.py` (writing `paper/generated/numbers.tex`
and generated table bodies), and `check_paper_numbers.py` fails the build if a
results numeral is typed by hand. `paper/generated/check_before_sections_edit.txt`
records the checker's 228-finding output on the pre-pipeline paper.

Main experiment: `agv_code/agv_code/results_hybrid_100j_20a_s1-10_strict/`
(regenerated by `python agv_compare.py`; 10 seeds, 100 jobs, 20 AGVs,
A/B/B2/C/WA, strict track rule). Its schedule metrics are bit-identical to
the earlier verification run kept in `results_verify_strict/`.

**Note on `results_hybrid/`:** a `python agv_compare.py --seeds 1-3 --jobs
50 --agvs 10` run overwrote the shared default folder, so it now holds a
50-job, 10-AGV, seeds-1-3 run. All scripts have been changed to write to
settings-encoding folders; nothing cites `results_hybrid/` for the main
results anymore.

The assignment baseline CSV is regenerated by running `python agv_baselines.py`
from `agv_code/agv_code/`; it is not hand-edited. Since the folder-name change,
every script writes to a settings-encoding output folder, and
`test_results_manifest.py` fails if a folder's jobs/AGVs/seeds/track rule no
longer agree with `results_manifest.json` or with the folder's own name.
